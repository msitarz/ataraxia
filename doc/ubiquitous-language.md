# Ubiquitous language

This file is the single source of truth for Ataraxia's shared vocabulary. Use
these terms consistently in discussions, specifications, code, and tests. Update
definitions as the model evolves; [ADRs](adr/) record the decisions behind
architectural changes. See [architecture.md](architecture.md) for how the
concepts fit together.

| Term | Defined in | What it is |
| ---------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Computable` | [compute/protocol.py](../src/ataraxia/compute/protocol.py) | A hashable graph-node specification. It declares named dependencies and supplies the runner that executes it; execution state belongs to that runner. |
| `Runner` | [compute/protocol.py](../src/ataraxia/compute/protocol.py) | The callable execution instance supplied by `Computable.factory()`. It receives dependency values at each step and may retain execution state. `SourceNode` retains its runner so `send()` and graph execution use the same instance. |
| `Provider` | [provider.py](../src/ataraxia/provider.py) | A hashable, context-managed iterator that supplies input items; for example, `BarProvider` reads bars from a CSV shard. `SourceNode` adapts a provider into the computation graph. |
| `Source` | [compute/protocol.py](../src/ataraxia/compute/protocol.py), [source.py](../src/ataraxia/source.py) | An iterable, context-managed `Computable` input node. The loop passes each yielded item to `send()` before evaluating the graph. `SourceNode` delegates iteration and resource management to its provider. Current `compute()` supports exactly one source. |
| `Sink` | [compute/protocol.py](../src/ataraxia/compute/protocol.py), [loop.py](../src/ataraxia/compute/loop.py) | The graph's primary endpoint. It declares its sources and may name an optional downstream `consumer`; the loop evaluates `consumer() or sink`, and the backtest returns that selected node's last result. |
| `consumer` | [compute/protocol.py](../src/ataraxia/compute/protocol.py), [broker.py](../src/ataraxia/broker.py) | An optional downstream `Computable` returned by a `Sink`. It receives the sink's value to aggregate it or perform final computation; `Broker` is the current example. |
| Strategy | [backtest.py](../src/ataraxia/backtest.py), [ADR 14](adr/0014-sink-module-file-special-attribute.md) | A caller-defined `Sink` whose runner derives values or `Signal`s from source data and features. A backtest module exports its sink class as `__sink__`, and backtesting constructs it with the source. |
| Feature | [feature.py](../src/ataraxia/feature.py), [ADR 3](adr/0003-feature-composition.md) | A composable `Computable` that derives a value from source data or other features. Features may be supplied by Ataraxia or defined with a strategy. |
| Work | [Work workflow](workflow.md#scope-and-sizing) | A bounded delivery increment with one independently verifiable, coherent capability or outcome, identified by its repository directory and governed by a local README contract. It is distinct from a trading [Feature](../src/ataraxia/feature.py). |
| Assignment return | [Executor guidance](executor.md#assignment-return), [Orchestrator guidance](orchestrator.md#review-and-return) | A bounded delegated scope and its applicable subordinate reviews completed for the named owner's review. It may be an intermediate artifact within a Work and does not mean that the Work's outcome is complete. |
| Acceptance criterion | [Work contract template](work-contract-template.md#acceptance-criteria) | An independently assessable condition or guarantee for a Work's outcome, verified from inspectable evidence under [Work acceptance](acceptance-tracing.md). |
| Shared constraint | [Work contract template](work-contract-template.md#inherited-constraints) | A parent-owned concept, invariant, responsibility, dependency direction, effect limit, or non-functional requirement that applies to child Works; local acceptance does not claim an unverified parent-owned system guarantee. |
| Algebraic data type | [Engineering guidance](engineering.md#code-style) | A data model composed from product types (fields required together) and sum types (one of distinct variants). In Python, a union of record variants can express a sum without a new framework. A finite tag alone does not express variant-specific fields, and static types do not replace external-input validation or guarantee exhaustive matching. |
| Pure function | [Engineering](engineering.md#pure-typed-decisions) | A function whose same explicit inputs produce the same outputs without I/O, environment/time/random/global-state dependence or argument mutation. Calling an effectful collaborator is an effect even through a Protocol. The guidance defines a design policy; it does not establish repository-wide implementation compliance. |
| Port and adapter | [Engineering](engineering.md#code-style) | A port is a collaborator contract defined by its consumer's needs, expressed with `typing.Protocol` and precise input/output/error/lifecycle ownership. An adapter implements that contract for a concrete mechanism and is supplied by composition. Dependencies point toward the consumer contract; core does not import concrete adapters. Ports may describe effects; they do not make their caller pure. Engineering guidance describes the policy using existing patterns. |
| Worktree | [Setup and Make interface](../CONTRIBUTING.md#getting-started), [leaf use](orchestrator.md#roles-and-delegation) | A Git working tree. A linked worktree has independent working files, index, and HEAD while sharing Git objects and repository refs. It is distinct from a Work's contract directory, a branch/ref, the Git repository, and a generic temporary directory or virtual environment. It is neither a security or permission boundary nor an independent full repository. |
| Evidence | [Work acceptance](acceptance-tracing.md#evidence) | Inspectable observed results used to assess a criterion, such as test execution results, measurements, artifacts, or independent review findings. A planned method or executable check alone is not evidence of its outcome. |
| Workflow Decision Record (WDR) | [WDR workflow](wdr-workflow.md) | A record of the rationale for a consequential delivery-workflow choice. Current rules remain in their authoritative owner. |
| Orchestrator | [Orchestrator handoffs](orchestrator.md) | The agent that owns a repository task's scope and context, assigns bounded repository changes, reviews the result, and returns it for maintainer review. |
| Definer | [Definer guidance](definer.md) | The agent assigned Work contract definition and serial coordination of shared parent-map edits. It returns the contract for independent orchestrator review and is distinct from an Executor implementing approved contracts. |
| Executor | [Executor guidance](executor.md) | The agent assigned bounded implementation under approved Work contracts, including code, tests, documentation, Investigation, or Evaluation execution. It returns the artifact and evidence for independent orchestrator review; contract definition belongs to the Definer. |
| Walking skeleton | [Progressive implementation](engineering.md#progressive-implementation) | An optional executable thin path through real composition and orchestration. Unfinished leaf operations may be stubbed and fake adapters may stand in for external effects; it demonstrates only the exercised composition and orchestration, not stubbed behavior. |
| Publisher | [Mechanical PR publication](publisher.md) | The operational subagent that pushes and creates or updates PRs from exact reviewed inputs. It is distinct from an Executor, which changes repository artifacts, and an Orchestrator, which retains review, acceptance, publication accountability, and maintainer handoff. |
| Investigation | [Investigations](work-definition.md#investigations) | A Work that answers a bounded question and produces a recommendation, comparing candidates when relevant. It distinguishes checked evidence from uncertainty and can use prototyping (exploratory implementation) for feasibility questions or supporting Evaluations for empirical evidence. Prototyping is a method within an Investigation, not a separate Work kind; its completion does not establish production readiness. |
| Evaluation | [Empirical evaluations](evaluation.md), [Work relationship](work-definition.md#evaluations) | A Work that owns empirical evidence for a bounded question from a declared protocol. It can stand alone or support an Investigation; its evidence is distinct from a recommendation or policy adoption. |
| Shard | [backtest.py](../src/ataraxia/backtest.py), [ADR 6](adr/0006-massive-parallelism-via-sharding.md) | An input-data partition processed independently for a strategy. Current backtesting reads bars from a CSV file for each shard, processes shards sequentially, and returns per-shard results. The CLI aggregates their account totals. |
| `Bar` | [bar.py](../src/ataraxia/bar.py) | An OHLCV input value. Current normalization supports CME index futures with four ticks per point. |
| `Signal` | [broker.py](../src/ataraxia/broker.py) | A strategy output that asks a broker to open a buy or sell market position with stop-loss and take-profit levels. |
| Position | [broker.py](../src/ataraxia/broker.py) | A broker record created from a `Signal` and its entry `Bar`; it tracks entry, exit, and realized or unrealized PnL. The current broker enters at the signal bar's close and evaluates exits from later bars. |
| Account | [broker.py](../src/ataraxia/broker.py) | The broker's current total realized PnL and unrealized PnL across its positions. |
| Broker | [broker.py](../src/ataraxia/broker.py) | A downstream `consumer` computable that turns `Signal`s and bars into an `Account`, open positions, and closed positions. |
