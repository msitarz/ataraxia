Generated schema inspection

`v2/ThreadStartParams.json` has `dynamicTools`, `baseInstructions`,
`developerInstructions`, `config`, `environments`, `cwd`, and policy/model
fields. It has no general `tools` property. `dynamicTools` accepts an array of
custom function specs or namespace specs and defaults to null; setting it to an
empty array could represent no caller-supplied dynamic functions. The schema
does not state that this disables Codex's built-in shell, search, MCP, browser,
image, or delegation tools. `config` is open-ended and does not establish
effective configuration by itself. `environments: []` explicitly disables
environment access for turns that do not provide a turn override.

`v2/TurnStartParams.json` has `input`, `additionalContext`, per-turn
`environments`, `permissions`, `sandboxPolicy`, `approvalPolicy`, `model`, and
collaboration settings. It has no `dynamicTools` or general `tools` field.
`additionalContext` adds client-provided fragments; it is not a context-removal
control. An empty environments list disables environment access for that turn,
not every built-in tool surface. `baseInstructions` and
`developerInstructions` are nullable strings in `thread/start`, but the schema
does not define empty/null semantics sufficient to establish that all inherited
or host context is absent.
