# Independent shallow clone readiness

Own an initially manual trusted-orchestrator preparation procedure using native
Git and existing `make setup` / `make verify-setup`. Prepare online before
restricted executor execution. The
[verified Investigation](https://github.com/msitarz/ataraxia/blob/c9a24b3f8cccfb9392ec12db2029dfe03887786d/doc/feat/reviewable-workflow-v2/trial-preparation/workflow-efficiency/shallow-executor-clones/environment-preparation/README.md)
is bounded Darwin Intel evidence, not support for all hosts or a model session.
The [parent](../README.md) owns the proposed flow and scheduling.

Deliver a short reviewed procedure and handoff using existing Work/evaluation
records, without a new record schema or framework. Before closure, promote the
lasting procedure to
[contribution guidance](../../../../../../../../CONTRIBUTING.md) and retain
evaluation-specific controls with the
[evaluation owner](../../../../../../../evaluation.md). Do not add a preparation
Make target, helper, cache filter or offline environment reconstruction.
Reuse native operations and existing evidence; do not add tests of upstream Git
or setup fixtures, or rerun the Investigation. Runtime owns sandbox enforcement,
actual start and exact-session resume; import owns accepted-output delivery.
Keep this leaf within a five-minute complete review. All criteria remain TODO.

## Acceptance

- **AC-1 TODO** Given a fresh final destination and frozen committed input,
  the procedure prepares an independent depth-one single-selected-branch clone
  at the exact recorded HEAD without tags, origin, alternates, hardlinked
  objects, extra source refs or dirty source inputs. It assigns the executor
  branch. Local `master` is the default selected branch/base under
  [contribution rules](../../../../../../../../CONTRIBUTING.md#work-branches-review-and-merge);
  overrides require explicit instruction. Changed input or an existing
  destination stops before overwrite or handoff.

  Validation: independently review the native command sequence and handoff
  record against the retained clone evidence, including `--no-local` or
  `file://` shallow transport, exact commit/refs, object independence and
  stopped gates. Any future manual check freezes the current selected input,
  tools/platform and final paths before execution; it is not a new experiment
  authorized by this plan.
- **AC-2 TODO** Existing locked online Make setup prepares fresh clone-local
  virtual environment, caches and installed pinned hooks in the final location;
  readiness is accepted before handoff. Sanitized configuration, resolved
  interpreter paths and permitted dependency reads are explicit. No old
  environment/cache or inherited source hooks supply readiness. Failure retains
  recoverable state and diagnostics without overwrite, silent full-history,
  installation-in-executor or wider-access fallback.

  Validation: manually review the procedure and readiness record against
  canonical setup/hook declarations and the verified report. Inspect editable
  links, interpreter and hook launch paths and readable dependency/cache content
  for source/history, answers, credentials and unintended external roots. Fresh
  caches alone establish no privacy guarantee. Further approved manual checks
  freeze the current condition and use its actual privacy controls, preserving
  failures; do not duplicate historical cache inventories.
- **AC-3 TODO** The handoff freezes permitted files/references and excludes
  prohibited current-tree answers/history evidence as required by the intended
  evaluation. Readiness under the actual intended restricted boundary confirms
  useful prepared tools/hooks and denied source/history/network access before
  executor launch; unsupported or failed controls block handoff.

  Validation: independently review the handoff and readiness checks using
  existing native boundary controls, required tool/runtime reads and clone-local
  scratch. Runtime independently rechecks its effective boundary before actual
  start/resume; preparation does not depend on a new launcher. Reuse the
  Investigation's bounded controls as evidence only for their original
  condition; any future check needs matching unrestricted controls and actual
  denials in the frozen current condition. Offline flags or absent origin do
  not prove isolation. Do not infer report/answer exclusion from the earlier
  run, whose clone permitted current-tree audit content, or infer model/session
  isolation from deterministic command checks.
